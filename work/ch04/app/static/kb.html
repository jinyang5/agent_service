知识库录入

贴一段文档就能进库:切块 → 双写 MySQL 与 Milvus → 现场检索自测
两条路:手工录入把正文贴在这一页上,预览什么样就入库什么样;离线建库把 data/kb/ 那几份材料交给作业跑,页面按的和终端敲的是同一条命令。 两条路共用一份切块实现与同一个双写顺序——先写 MySQL 记「待向量化」,再进 Milvus 回标「已向量化」, 中途挂了重跑捡 pending 就能补齐。

① 手工录入 正文贴这里

按标题层级切、超长递归切、块间重叠裁到最近句号、大表格按行拆并复制表头—— 这几条在下面的预览里逐块标出来(标不出触发的就是没触发)。 查重按「问法 + 正文」的指纹,同一份正文重复录入会全跳过。

② 建库材料 —

data/kb/ 下的文档是离线建库的输入。这里的块数就地切出来(dry-run:不写库、不碰 Milvus、不调上游),点「看切块」把结果送到上面的预览区逐块看。

③ 对话挖知识 —

历史客服对话分批喂给 LLM 抽问答对,先落暂存表,再整体去重入库。 三个状态的落差就是去重那一刀:抽出多少、留下多少、丢了多少。

④ 向量化与双写 —

MySQL 是原文权威源,Milvus 只存向量。幂等靠 vectorize_status:写 MySQL 记 pending, 嵌入后按主键 upsert 进 Milvus、回标 done。故意中断建库,再按「向量化待补块」, 漏掉的块会被捡起来补齐——这一条不用回终端演。

⑤ 检索自测 换个说法问一句

问句向量化后到 Milvus 按相似度取 Top-K。「邮费是多少」库里一个字都没写过, 靠的是与「运费」那块语义相近——词面查表做不到这件事。

⑥ 最近入库

按 id 倒序取最近 12 块,看录进去的东西长什么样、状态到哪一步了。
